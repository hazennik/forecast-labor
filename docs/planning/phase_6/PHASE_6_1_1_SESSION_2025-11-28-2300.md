### 2. Re-applied Weather CSV Implementation ⚠️ (Needs URL Verification)

**File Modified:** `etl/public/weather/weather_etl.py`

**Changes Implemented:**
- Replaced API approach with CSV bulk file downloads
- Downloads gzipped CSV files from NOAA Storm Events Database
- URL: `https://www.ncei.noaa.gov/pub/data/swdi/stormevents/csvfiles/`
- File format: `StormEvents_details-ftp_v1.0_d{YEAR}_c{CREATION_DATE}.csv.gz`
- Implements multiple creation date attempts to find available files
- Parses CSV format:
  - `BEGIN_YEARMONTH` + `BEGIN_DAY` → `date`
  - `DEATHS_DIRECT` + `DEATHS_INDIRECT` → `deaths`
  - `INJURIES_DIRECT` + `INJURIES_INDIRECT` → `injuries`
  - `DAMAGE_PROPERTY` (string format like "10.00K", "1.50M") → `damage_millions`
- Added `_parse_damage()` helper to convert damage strings to millions

**Issue:** File creation dates in URLs need manual verification
- Attempted dates: `20241016`, `20240916`, `20240816`, `20231116`
- None found (404 errors for all attempts)
- **Action Needed:** Manual inspection of https://www.ncei.noaa.gov/pub/data/swdi/stormevents/csvfiles/ to find correct creation dates for 2023, 2024, 2025 files

**Rationale:** CSV approach is correct per `docs/planning/WEATHER_DATA_PRODUCTION_STRATEGY.md`:
- NOAA Storm Events has NO JSON API
- CSV bulk files are the official and only source
- Files updated monthly by NOAA
- Monthly updates sufficient for monthly labor forecasting
